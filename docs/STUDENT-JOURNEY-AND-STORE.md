# رحلة الطالب والمتجر الصادق ومراجعة الخطط

آخر تحديث: 2026-11-13 — الإصدار المحلي `20261113-2` (غير منشور).

## الهدف

إدخال الطالب الجديد إلى خطة واقعية بوقته، دون إنشاء نظام موازٍ للاقتصاد أو لمسار القرآن، ودون عرض مكافآت غير موجودة. كل ما هنا يعيد استخدام بيانات الأكاديمية القائمة.

## إعادة الاستخدام (لا تكرار)

| الحاجة | المصدر القائم | ما أُضيف |
|---|---|---|
| تقدم الرحلة والإجابات | `academy_records` بمجموعة `student_journey` | لا جدول جديد |
| XP | `point_events` / رصيد `achievement` | لا محفظة جديدة |
| Coins | `store_items` / `store_redemptions` / رصيد `store` | لا عملة جديدة |
| مسار القرآن | `quran_paths` والدوال الحالية | كاتبا مسار/خطة مشتركان |
| خطة القرآن | `academy_records` بمجموعة `quran_plan` | لا جدول جديد |
| الاعتماد | صفحة القرآن للشيخ | تبويب «خطط الطلاب» |

## تدفق الرحلة

1. الطالب يبدأ من «عالمي» أو من صفحة القرآن غير المسجّلة.
2. ثمانية أسئلة، سؤال واحد في كل مرة:
   - مقدار المحفوظ، الرواية، دقائق اليوم، الهدف، مستوى الإتقان، الصعوبة، الورد، يوم الاستدراك.
3. كل إجابة تُحفظ فورًا؛ إغلاق الصفحة لا يفقد التقدم.
4. بعد اكتمال الإجابات تُعرض ثلاثة خيارات (خفيفة/متوازنة/مكثفة) مع تقدير الوقت لا المال.
5. إذا تجاوز الخيار وقت الطالب المعلن، يلزم تأكيد صريح (`acknowledge_over_budget`).
6. التطبيق ينشئ/يحدّث مسار القرآن وخطة الأسبوع عبر الدوال المشتركة نفسها.
7. الخطة تصبح `approval_status: pending`، ويمكن للطالب قبول التوصية أو تعديل الخيار.
8. الشيخ يراجع الإجابات والتكلفة والملاءمة، ثم:
   - `approved`: تُثبَّت الخطة الحالية.
   - `changes_requested`: ملاحظة إلزامية، وتعود الرحلة إلى `in_progress` للتعديل وإعادة الإرسال.
9. الاعتماد لا يمنح نقاطًا، ولا يعدّل سجل الحفظ، ولا يوقف تعلم الطالب.

## المتجر الصادق

- لا يعرض للطالب إلا صفوف `store_items` النشطة التي أدخلها المدير فعلًا.
- لكل مادة: الاسم، الوصف، الرمز، التكلفة، المخزون (أو بلا حد)، حد الطالب، الترتيب.
- التوصيات تُشتق من الرصيد الحقيقي والمخزون والاستخدام:
  - `affordable`: متاح الآن.
  - `nearest`: أقرب مكافأة مع المبلغ المتبقي ونسبة التقدم.
  - `locked`: تحتاج رصيدًا أكبر.
  - `sold_out` / `maxed`: نفدت أو بلغت حدّها، وتُعرض بوضوح دون إتاحة الطلب.
  - `empty`: لا مكافآت معتمدة، مع توضيح أن الرصيد محفوظ.
- طلب الصرف يحجز الرصيد والمخزون فورًا؛ الرفض يعيد الرصيد والمخزون؛ التنفيذ نهائي.
- شروط الصرف ظاهرة قبل الطلب (مراجعة بشرية، حجز الرصيد، عدم الإلغاء بعد التنفيذ، فصل نقاط الإنجاز عن رصيد المتجر).
- اقتراحات المدير في الواجهة **قوالب غير محفوظة** ولا تظهر للطالب؛ لا بذر تلقائي ولا منتجات تجريبية في الإنتاج.

## واجهات API

| المسار | الصلاحية | الوظيفة |
|---|---|---|
| `GET /api/journey` | طالب (حسابه) | حالة الرحلة، الأسئلة، التوصية |
| `POST /api/journey` | طالب | حفظ إجابة واحدة والتحقق منها |
| `POST /api/journey/apply` | طالب | تطبيق الخيار وإنشاء المسار والخطة |
| `GET /api/journey/review?status=` | شيخ/إدارة ضمن النطاق | قائمة المراجعة والملخصات |
| `POST /api/journey/review` | شيخ/إدارة ضمن النطاق | اعتماد أو طلب تعديل بملاحظة |
| `GET /api/store/items` | طالب/طاقم | كتالوج + توصيات الطالب |
| `POST /api/store/items` | مدير فقط | إضافة/تعديل/إخفاء مكافأة حقيقية |
| `POST /api/store/redeem` | طالب | طلب صرف مع حجز الرصيد |
| `POST /api/store/redemptions/:id/decision` | شيخ/إدارة ضمن النطاق | قبول/رفض/تنفيذ بقرار موثّق |

## الاختبارات

- `scripts/journey-store-test.mjs`: 93 فحصًا على قاعدة نظيفة (ترحيلات 0001–0006):
  - استئناف الرحلة، رفض الأسئلة/القيم غير الصالحة، عزل الطلاب، منع الطاقم من الإجابة نيابةً عن الطالب.
  - التوصية، تجاوز الوقت، التأكيد الصريح، إنشاء المسار والخطة، حفظ «بلا يوم راحة».
  - نطاق الشيخ، طلب التعديل بملاحظة، إعادة الإرسال، الاعتماد، عدم منح نقاط خفية.
  - انتقال الطالب إلى فوج جديد: تنتقل صلاحية اعتماد خطته إلى شيخ الفوج الجديد، ويُحجب عنها شيخ الفوج القديم، مع ظهور الفوج الحالي في المراجعة.
  - المتجر: منع التكلفة الصفرية والمخزون السالب، المدير فقط، إخفاء غير النشط، النفاد، الحد لكل طالب، الصرف، الرفض والاسترجاع، تعديل/إخفاء المادة.
- `npm run check` يتضمن فحص الصياغة وحراسات `security-check.mjs`.
- فحص متصفح يدوي: الرحلة والاستئناف، متجر الطالب، إدارة المتجر، مراجعة الخطط.

## القيود والقرارات المعلّقة

- **لم يُنشر** هذا الإصدار إلى الإنتاج، ولا توجد ترحيلات إنتاجية جديدة له.
- كتالوج المتجر الحقيقي (الأسماء، التكاليف، المخزون، الصور، الشروط) لم يقدمه المالك بعد.
- أرقام التثبيت و5 أيام العمل مقترح ينتظر اعتماد الشيخ.
- لا تصحيح تلاوة آلي، ولا فتوى مستقلة، ولا مساعد AI مفعّل.
- بطاقة الطالب وبطاقة الزيارة منفصلتان، ولا تُخلطان.
