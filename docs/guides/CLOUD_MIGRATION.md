# V10 — Cloud migration blueprint

هذه النسخة جهزت الحدود بين الواجهة والخادم وبين قاعدة البيانات حتى لا نربط أسرار السحابة داخل التطبيق.

## المطلوب للنسخة الإنتاجية
1. إنشاء مشروع قاعدة بيانات/مصادقة سحابية.
2. إنشاء الجداول:
   users, profiles, groups, memberships, posts, post_reads,
   notifications, attendance, student_progress, reports,
   subjects, lessons, schedules, tests, grades.
3. تفعيل Auth حقيقي.
4. منع قراءة بيانات طالب إلا من الطالب نفسه أو ولي أمره أو المعلم/الإدارة المخولين.
5. عدم وضع مفتاح إداري سري داخل الواجهة.
6. تفعيل HTTPS.
7. نسخ احتياطي.
8. سجل تدقيق Audit Log.
9. سياسة خصوصية وشروط استخدام.
10. اختبار حسابات الإدارة/المعلم/الطالب/ولي الأمر قبل الإطلاق.

## لماذا لم أضع بيانات سحابية وهمية؟
لأن ذلك سيعطيك تطبيقًا يبدو متصلًا لكنه في الحقيقة ليس كذلك. الربط الحقيقي يحتاج حسابًا في مزود السحابة ومفاتيح/إعدادات يملكها صاحب الأكاديمية.

## بنية الأدوار
admin:
  إدارة كاملة.

teacher:
  إدارة طلابه وأفواجه ومنشوراته وتقارير المتابعة المسموحة.

student:
  بياناته وتقدمه ومنشورات الأفواج التي ينتمي إليها.

parent:
  الأبناء المرتبطون به فقط، وتقاريرهم وجدولهم وتنبيهاتهم.

## الخطوة التالية
بعد إدخال بيانات مزود السحابة، يمكن تحويل طبقة DB من JSON إلى SQL/Cloud دون إعادة بناء واجهة V9 من الصفر.
