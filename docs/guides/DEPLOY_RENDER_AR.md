# نشر أكاديمية الإحسان V49 على Render

## ما تم تجهيزه
- ملف `render.yaml` لخدمة التطبيق.
- صورة Docker لا تعتمد على وجود `package-lock.json` في الحزمة الحالية.
- ملف `.dockerignore` يستبعد بيانات التشغيل والأسرار ولقطات حسابات الاختبار من صورة التطبيق.
- ملف `.gitignore` يستبعد محتويات `data/` من Git.

## قبل النشر
1. ارفع **حزمة المصدر المنقّحة فقط** إلى مستودع GitHub خاص.
2. أنشئ قاعدة PostgreSQL في Render، ثم انسخ **Internal Database URL**.
3. اربط المستودع بـ Render باستخدام Blueprint من ملف `render.yaml`.
4. عيّن المتغيرات المطلوبة في إعدادات الخدمة:
   - `DATABASE_URL`: رابط PostgreSQL الداخلي.
   - `ACADEMY_BOOTSTRAP_ADMIN_NAME`: اسم المدير الأول.
   - `ACADEMY_BOOTSTRAP_ADMIN_EMAIL`: بريد المدير الأول.
   - `ACADEMY_BOOTSTRAP_ADMIN_PASSWORD`: كلمة مرور قوية وفريدة لا تقل عن 12 محرفًا.
5. تحقّق من `/api/health` و`/api/ready`.

## نقل البيانات الأصلية — لا تتجاوز هذه الخطوة
الحزمة الأصلية تحتوي بيانات حقيقية في `data/db.json`؛ لذلك لا تُرفع إلى GitHub ولا تُضمّن في صورة Docker. احتفظ بنسخة احتياطية خارج المستودع.

لا تعتبر النشر مكتملاً حتى تنقل بيانات `data/db.json` إلى PostgreSQL عبر أداة `npm run migrate:postgres` بعد ضبط `DATABASE_URL` و`ACADEMY_DB_FILE` على نسخة البيانات المقصودة، ثم تتحقق من عدد المستخدمين والأفواج وسجلات الحضور والحفظ، وتجرب الدخول بحسابات الإدارة والمعلم والطالب وولي الأمر.

**تنبيه:** أداة الترحيل تكتب محتويات الملف المصدر إلى قاعدة PostgreSQL وتستبدل سجلات التخزين الحالية؛ لا تشغّلها على قاعدة فيها بيانات مهمة قبل أخذ نسخة احتياطية والتحقق من مصدر الملف ووجهة قاعدة البيانات.

## ملاحظات
- لا ترسل كلمات المرور أو روابط قواعد البيانات في المحادثة أو المستودع.
- إعداد Render لا ينشئ قاعدة بيانات مدفوعة تلقائيًا؛ اختر الخطة والتكلفة بنفسك.
- نجاح الاختبارات المحلية لا يغني عن اختبار النشر الفعلي والترحيل.
