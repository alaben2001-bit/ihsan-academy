# V30 — طبقة التخزين الحقيقية القابلة للتبديل

## ما الذي تغير؟
- فصل تخزين الأكاديمية عن منطق الخادم عبر Storage Adapter.
- أبقينا JSON هو التخزين الافتراضي الحالي حتى لا تتغير بيانات التطوير دون قصد.
- إضافة `JsonStorageAdapter` مع كتابة ذرّية وفحص صحة SHA-256.
- إضافة `SqliteStorageAdapter` باستخدام SQLite المدمج في Node.js 22+.
- دعم حفظ المجموعات كسجلات JSON داخل SQLite مع `academy_meta` للحقول الكائنية، كجسر ترحيل متوافق مع D1/SQLite.
- الحفاظ على السجلات التي لا تملك `id` دون إدخال معرف اصطناعي إليها عند القراءة.
- إضافة هجرة JSON → SQLite مع تحقق round-trip وmanifest ومبدأ التراجع.
- إضافة SQLite → JSON لاستعادة نسخة قابلة للرجوع.
- إضافة نسخ احتياطي SQLite مع checkpoint قبل النسخ.
- إضافة `/api/health` لفحص التخزين، و`/api/admin/health/storage` للفحص الإداري التفصيلي.
- تحديث صفحة إعدادات الإدارة لتعرض نوع التخزين الحالي.
- دعم `ACADEMY_STORAGE=json|sqlite`، مع إبقاء وضع السحابة القديم محميًا حتى لا يوحي بوجود اتصال غير حقيقي.

## ما لم يتغير
- لا توجد إعادة بناء للواجهة أو تغيير في مفهوم الأكاديمية.
- الصلاحيات والمنطق القرآني والتربوي الحاليان باقِيان.
- JSON لم يُلغَ ولم يصبح SQLite إلزاميًا تلقائيًا.

## متطلبات SQLite
- يحتاج مسار SQLite في هذه النسخة إلى Node.js 22+ بسبب `node:sqlite`.
- لا نضع أي مفاتيح سحابية أو أسرار داخل المشروع.

## الأمان
- لا يُكشف مسار ملف SQLite في واجهة الصحة العامة.
- فحص الصحة الإداري يتطلب دور المدير.
- الهجرة لا تستبدل المصدر قبل نجاح التحقق.
- عند فشل الهجرة إلى ملف SQLite موجود، توجد نسخة pre-migration لاسترجاع الهدف.
