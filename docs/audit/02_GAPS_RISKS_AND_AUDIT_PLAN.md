# سجل الفجوات والمخاطر وخطة التدقيق

الحالة: جرد ثابت أولي بتاريخ 2026-10-09.

## 2. نقاط لا يجوز حسمها دون اختبار

- هل كل مسار API يفرض الصلاحيات في الخادم، بما فيها الطلبات المباشرة التي تتجاوز الواجهة؟
- هل تُعزل المدارس والأفواج والفرق في القراءة والتعديل والحذف والتصدير والرسائل والتقارير؟
- هل يستطيع ولي الأمر رؤية الأبناء المرتبطين به فقط؟ وهل يمكن تزوير ربط الأبوة؟
- هل يتغير نطاق المعلم أو المشرف عند النقل أو حذف العضوية أو تغيير الدور؟
- هل تبقى بيانات الطالب والاختبارات والحضور بعد إعادة تشغيل الخدمة أو إعادة النشر؟
- هل ترحيلات PostgreSQL قابلة للتكرار بأمان، وهل تتعامل مع فشل جزئي أو بيانات قديمة؟
- هل النسخ الاحتياطي قابل للاستعادة فعليًا؟ هل يُخزن خارج مسار التطبيق؟ ومن يملك الوصول إليه؟
- هل الجلسات تنتهي وتُلغى عند تغيير كلمة المرور/الدور؟ وهل CSRF وRate limiting مطبقان على المسارات الحساسة؟
- هل توجد حماية من تخمين كلمات المرور، وتكرار إرسال النماذج، ورفع الملفات الخطرة أو الكبيرة؟
- هل واجهة الهاتف للمدير العام والشيخ ومدير المدرسة قابلة للاستخدام دون تمرير أفقي أو أزرار متداخلة؟
- هل مفاتيح الإجابة مخفية عن الطالب، وهل تمنع API كشفها قبل التسليم؟
- هل إجابات الطالب المفتوحة تُراجع من المعلم، ولا تُصحح آليًا بطريقة توهم بالدقة؟
- هل بيانات الدخول الافتراضية/التجريبية أو بيانات شخصية موجودة في الكود أو السجلات أو الصور؟
- هل الموقع القديم يعيد التوجيه إلى الخدمة الأساسية فعلًا، وهل اختبار الصحة لا يخفي فشل الوظائف الفعلية؟

## 3. مصفوفة مراجعة الصلاحيات المطلوبة

| الدور | السماح المتوقع | محاولات الرفض الإلزامية |
|---|---|---|
| المدير العام | إدارة المنصة والمدارس والصلاحيات والسياسات حسب التفويض | لا تُسند صلاحيات ضمنية إلى دور أدنى ولا تُخفى تغييرات البيانات |
| مدير المدرسة/الشيخ المسؤول | إدارة مدرسته وأفواجه وطلبته ومحتواها ضمن التفويض | الوصول إلى مدرسة أخرى أو منح صلاحيات عامة |
| المعلم | طلبته ودروسه وحضورهم وتقييمهم | فتح ملف طالب خارج نطاقه، أو تغيير أدوار الإدارة |
| المشرف الرئيسي | الفرق والطلبات المسندة إليه حسب سياسة الأكاديمية | تغيير تعيينات المعلمين أو قراءة الرسائل الحساسة دون حاجة |
| مشرف الفريق | فريقه ومهامه المحددة فقط | قراءة/تعديل فريق آخر أو تحويل نفسه إلى معلم/مدير |
| الطالب | ملفه ورحلته ودروسه ونتائجه ورسائله المسموحة | قراءة طالب آخر أو مفتاح إجابة أو بيانات إدارية |
| ولي الأمر | الأبناء المرتبطون به والتقارير المسموحة | الوصول إلى طالب آخر أو تعديل سجلات المدرسة |

## 4. دورة حياة البيانات التي يجب اختبارها

لكل كيان أساسي (حساب، طالب، مدرسة، فوج، فريق، عضوية، خطة، درس، سؤال، محاولة، حضور، رسالة، مرفق، تقرير):
1. إنشاء صحيح وإنشاء ناقص/غير صالح.
2. قراءة من المالك ومن مستخدم خارج النطاق.
3. تعديل حقل مسموح ومحاولة تعديل حقل محمي.
4. نقل الطالب أو المشرف بين النطاقات.
5. إلغاء/رفض/أرشفة/حذف، مع التحقق من أثر ذلك على السجلات المرتبطة.
6. منع التكرار والتعارض وإعادة الإرسال.
7. فشل قاعدة البيانات أو انقطاع الشبكة أثناء العملية.
8. التحقق من سجل التدقيق وعدم تسريب أسرار.
9. التأكد من عدم فقد البيانات بعد إعادة التشغيل والترحيل.
10. اختبار استعادة نسخة احتياطية في بيئة منفصلة.

## 5. تدقيق المحتوى والتقييم

- كل مادة لها هدف ومستوى ونوع تعلم واضح.
- كل درس ديني يميز النص المنقول عن الشرح والتأمل، ويذكر المصدر والدرجة التي راجعه بها مختص.
- لا تُنشر رواية ضعيفة أو نسبة قول إلى عالم دون تحقق.
- لا تُقدّم ادعاءات علاج الأمراض النفسية أو الجسدية بوصفها سهلة أو مضمونة العلاج.
- لا تُقدّم أحكامًا مالية أو تبرعات أو تدخلات عملية دون ضوابط.
- أسئلة الاختيار من متعدد: خيارات صحيحة، إجابة واحدة واضحة، تفسير، ونقاط.
- الأسئلة المفتوحة: معيار تصحيح وتعليق ومراجع بشري، مع إخفاء مفتاح الإجابة عن الطالب.
- التكرار المتباعد يتبع أداء الطالب، لا عددًا عشوائيًا من الاختبارات.
- التقارير تصف التقدم والمساعدة المطلوبة ولا تصف الطالب بالفشل أو تقارن قيمته بغيره.

## 6. تدقيق واجهة الهاتف

يجب اختبار 320px و360px و390px و768px وسطح المكتب، لكل دور ذي واجهة مختلفة:
- الإدارة العليا: ترتيب الأولويات والإجراءات الرئيسية أولًا، وتقليل ازدحام البطاقات.
- الشيخ/مدير المدرسة: حضور وتسميع ومراجعة وإضافة ملاحظات بأقل خطوات.
- الطالب: «ماذا أفعل الآن؟» مع القرآن والمهام والرحلة في مكان واضح.
- ولي الأمر: ملخص مفهوم للحضور والتقدم والملاحظات دون إغراق في التفاصيل.
- RTL، تكبير الخط، لوحة المفاتيح، النوافذ المنبثقة، حالات عدم وجود بيانات، والتحميل/الخطأ.
- لا تُعد CSS الموجود دليلًا على نجاح اختبار بصري فعلي.

## 7. ترتيب المعالجة

1. أمان البيانات والصلاحيات والجلسات.
2. سلامة التخزين والترحيلات والنسخ الاحتياطي والاستعادة.
3. استكمال التدفقات التعليمية الحرجة: القرآن والحضور والمراجعة والاختبارات.
4. إكمال مراجعة الإجابات المفتوحة والتقارير.
5. واجهة الهاتف لكل دور.
6. إكمال المحتوى ومراجعته علميًا وتربويًا.
7. ميزات المجتمع والصراحة والتحديات والمراسلة بعد سياسة الخصوصية.
8. التبرعات والتطبيق الأصلي بعد تحقق قانوني وتقني مناسب.

لا تُجرى تغييرات على الكود أو بيانات الإنتاج في هذه المرحلة؛ هذا سجل التدقيق وخطة التحقق فقط.
