## 2. بنية المشروع

| المسار | المسؤولية الظاهرة |
|---|---|
| `server/server.js` | خادم Node.js ومسارات API الرئيسية؛ نحو 1,827 سطرًا وقت الفحص |
| `server/advanced.js` | خدمات ومسارات إضافية |
| `server/services/core.js` | منطق خدمات المجال |
| `server/repositories/core.js` | طبقة الوصول إلى بيانات المجال |
| `server/storage/index.js` | محولات التخزين وإدارة القراءة/الكتابة |
| `server/storage/postgres.js` | محول PostgreSQL |
| `server/educational-content.js` | بيانات تمهيدية للمواد والدروس والأسئلة ورحلة الطالب |
| `assets/app.js` | منطق واجهة المستخدم |
| `assets/app.css` | التنسيق العام |
| `assets/admin-mobile.css` | تحسينات الهاتف للوحة الإدارة العليا |
| `index.html`, `privacy.html`, `offline.html` | واجهات وصفحات ثابتة |
| `migrations/` | تسعة ملفات ترحيل SQL مرقمة من 001 إلى 009 |
| `production_schema.sql` وملفات schema الأخرى | مخططات إنتاج/إصدارات سابقة؛ يلزم توحيد مرجعيتها في التدقيق |
| `tests/smoke.js` | اختبارات دخانية للتخزين والسلوك الأساسي |

| `tools/` | نسخ احتياطي، استعادة، ترحيل، وفحوص تخزين |
| `.github/workflows/ci.yml` | GitHub Actions: تثبيت الاعتماديات، `npm test`، وبناء Docker |
| `Dockerfile`, `render.yaml`, `deploy/` | إعداد الحاوية والنشر والتشغيل الذاتي |
| `docs/`, `release-notes/` | أدلة التشغيل، الهيكلة، المناهج، الأمن، وتاريخ التطوير |

## 3. الوظائف التي توحي بها الشيفرة والتوثيق

- إدارة الحسابات والأدوار والمدارس والأفواج والفرق.
- برامج تعليمية ومناهج ومحتوى تمهيدي.
- القرآن: الحفظ والمراجعة وملف الطالب القرآني ضمن تاريخ التطوير الموثق.
- الحضور والواجبات والاختبارات والأسئلة والتقارير.
- مكتبة المحتوى والتواصل والإشعارات.
- تخزين قابل للاختيار: JSON وSQLite وPostgreSQL.
- ترحيلات قاعدة بيانات، فحوص صحة، ووسائل نسخ احتياطي واستعادة.
- إعدادات للجلسات وCSRF وملفات تعريف الارتباط الآمنة وسياسات HTTP؛ وجود الكود لا يثبت صحة الإعداد الفعلي على الخدمة المنشورة.
- واجهة عربية RTL، مع ملف خاص لتحسين تجربة الإدارة العليا على الهاتف.

## 6. ما لم يُفحص أو يُثبت بعد

- لم تُقرأ بيانات PostgreSQL الإنتاجية أو تُعدّل، ولم تُجرَ عملية كتابة/حذف فيها.
- لم تُراجع قيم الأسرار أو متغيرات بيئة Render.
- لم يُنفّذ اختبار قبول شامل على الموقع الحي بجميع الحسابات والأدوار.
- لم تُثبت سلامة جميع حدود الصلاحيات بمجرد قراءة أسماء الملفات أو نجاح CI.
- لم يُثبت أن بيانات المستخدمين الحقيقية تتطابق مع مخطط قاعدة البيانات الحالي.
- لم يُنفّذ اختبار أداء، أو استعادة نسخة احتياطية فعلية، أو اختبار اختراق.
- لم يُنشأ تطبيق Android أصلي أو يُختبر نشره على Google Play؛ الموجود حاليًا مشروع ويب وفق الملفات التي جرى جردها.
