# تنظيم المستودع

## مصدر الحقيقة

النسخة التي تُبنى وتُنشر حاليًا هي `deploy/cloudflare/`. تُدار واجهة API في `src/index.js`، والواجهة في `site/`، والمخطط عبر `migrations/`، والفحوصات عبر `scripts/`.

## ما يجب إبقاؤه منفصلًا

- **الإنتاج الحالي:** Cloudflare Pages Functions وD1.
- **المصادر التاريخية:** ملفات Node.js وPostgreSQL وملفات ترحيلها في الجذر. لا تدخل في بناء Cloudflare الحالي؛ تُحفظ فقط للرجوع أو استعادة بيانات قديمة عند الحاجة.
- **البيانات الحية:** قاعدة D1 وسجلات الطلاب؛ لا تدخل ضمن إعادة ترتيب الملفات أو حذف التكرارات النصية.

## قواعد منع التراكم

1. ضع أي كود جديد خاص بالمنصة في `deploy/cloudflare/`، ولا تنسخ نسخًا ثانية من ملف الواجهة إلى الجذر.
2. أضف اختبارات الرجوع في `deploy/cloudflare/scripts/security-check.mjs` عندما تتغير قاعدة سلوك مهمة.
3. أضف تغييرات مخطط D1 في ملف ترحيل جديد وفريد، ولا تعِد تسمية ملف طُبّق على قاعدة حية.
4. عند تعديل CSS، أزل القواعد المتطابقة فقط؛ لا تحذف قواعد متشابهة بصريًا إذا كانت في نطاق استجابة أو سمة مختلفة.
5. حدّث إصدار ملفات الواجهة وذاكرة PWA معًا، ثم شغّل `npm run check` و`npm run prepare:assets`.
6. لا تعتبر نجاح البناء إثباتًا لاختبار كل دور أو كل مسار API.
