# أكاديمية الإحسان في بناء الإنسان — V63

منصة عربية لإدارة الحياة التعليمية والقرآنية: الطلبة، الأفواج، الحضور، الحفظ والمراجعة، التقييمات، الواجبات، التواصل، المحتوى، وتقارير المتابعة. الواجهة عربية باتجاه RTL، مع خادم Node.js وطبقة تخزين قابلة للتبديل.

## النسخة المنشورة

- **الرابط:** https://ihsan-academy-frankfurt.onrender.com
- **المستودع:** https://github.com/alaben2001-bit/ihsan-academy
- **الاستضافة:** Render، منطقة Frankfurt.
- **قاعدة البيانات:** PostgreSQL مخصصة للمشروع في المنطقة نفسها.
- **الفحص العام:** `GET /api/health`.
- **الاختبارات الآلية:** GitHub Actions — https://github.com/alaben2001-bit/ihsan-academy/actions

> نجاح بناء Docker ونشر الخدمة لا يثبت وحده أن تسجيل الدخول الإداري وكل مسارات قاعدة البيانات قد اختُبرت عمليًا. يجب إجراء اختبار قبول فعلي بعد النشر، والتأكد من أن البيانات تبقى بعد إعادة تشغيل الخدمة. لا تضع كلمات المرور أو روابط قواعد البيانات السرية في المستودع أو في البلاغات.

## إعداد التخزين

- `ACADEMY_STORAGE=json` — تخزين JSON المحلي.
- `ACADEMY_STORAGE=sqlite` — SQLite ويتطلب Node.js 22+.
- وضع PostgreSQL يحتاج `DATABASE_URL` أو `ACADEMY_POSTGRES_URL` في إعدادات البيئة السرية.
- `npm run health:storage` — فحص التخزين.
- `npm run health:postgres` — فحص PostgreSQL.
- `npm run backup:postgres` و`npm run restore:postgres` — أدوات النسخ والاستعادة؛ يجب اختبار الاستعادة على نسخة منفصلة قبل الاعتماد عليها.

## نقاط تشغيل يجب إغلاقها قبل الاعتماد الكامل

1. إجراء اختبار قبول حي: فتح الصفحة، تسجيل الدخول بحساب المدير، تجربة مسار قراءة وكتابة، ثم إعادة التشغيل والتحقق من استمرار البيانات.
2. التأكد من تهيئة حساب المدير الأول من متغيرات `ACADEMY_BOOTSTRAP_ADMIN_*` السرية، دون تخزين كلمة مرور ثابتة في الشيفرة.
3. تنفيذ نسخة احتياطية ثم تجربة استعادتها في قاعدة اختبار.
4. إضافة اختبارات آلية مستقلة لتسجيل الدخول، الجلسات، صلاحيات الأدوار، والحدود بين الأفواج.
5. التحقق من سياسة الاحتفاظ بالبيانات والخصوصية ومراقبة أخطاء الإنتاج.

## ما الجديد في V18 — النسخة المحسّنة
- **المعلم:** قوائم اختيار بدل كتابة s1/t1 (الفوج، التاريخ، حالة الحضور، الاختبار).
- **الحضور الجماعي:** كشف بأسماء الفوج وأربع حالات (حاضر/متأخر/غائب/غائب بعذر) وحفظ الجميع مرة واحدة، وإعادة الحفظ تعدّل ولا تكرّر.
- **إنشاء الاختبارات من الواجهة:** العنوان، المادة، الفوج، التاريخ، الدرجة القصوى، الوصف.
- **جدول الدرجات:** الطالب | الدرجة | ملاحظة، مع التحقق من الدرجة القصوى في الخادم.
- **ملف الطالب (المركز):** نظرة عامة، الحضور، المنهج، الحفظ، المراجعة، الاختبارات والدرجات، الأهداف، الملاحظات، التقرير.
- **ملاحظات المعلم:** التصنيف (تعليمي/سلوكي/تحفيزي/متابعة) + خيار «مشاركة مع الطالب وولي الأمر». الافتراضي: للمعلمين فقط.
- **التقرير الشهري التلقائي:** يُحسب من الحضور والدرجات والحفظ والأهداف والملاحظات، ويولّد ملخصًا ونقاط قوة وما يحتاج تحسينًا، ويقارن الطالب بنفسه في الشهر السابق فقط. يمكن حفظه في السجل.
- **الطباعة / حفظ PDF:** زر «طباعة / حفظ PDF» يفتح تقريرًا بتنسيق A4 جاهزًا للطباعة أو الحفظ كـ PDF من المتصفح. (ملف PDF مولَّد من الخادم مؤجل إلى V18.)
- **لوحة ولي الأمر:** أبناؤه فقط، ولكل ابن ملف كامل للقراءة فقط وتقرير شهري، وتُعرض له الملاحظات المشاركة فقط.
- **التصميم:** عربي RTL، أخضر/بيج/أبيض، يعمل على الهاتف والكمبيوتر.
- **V18 — تجربة الدرس:** يمكن للطالب فتح الدرس وقراءة هدفه ومحتواه ومدة تقديرية، ثم تسجيل الإكمال من داخل نافذة الدرس.
- **V18 — استكمال التعلم:** يظهر للطالب الدرس التالي مباشرة في بطاقة «الخطوة التالية».
- **V18 — البحث:** بحث فوري داخل قائمة الدروس.
- **V18 — عزل الدروس:** مسار عرض الدرس يتحقق من صلاحية الوصول من الخادم قبل إرجاع المحتوى.

## الأمان (يُطبَّق في الخادم)
- الدور يؤخذ من الجلسة فقط؛ أي role أو student_id أو parent_id من المتصفح لا يمنح شيئًا.
- الطالب يرى نفسه فقط، وولي الأمر أبناءه فقط، والمعلم طلاب أفواجه فقط (جدول `teacher_groups`)، والإدارة الكل.
- الأفواج والمنشورات والإشعارات والاختبارات والحفظ والأهداف كلها مفلترة حسب النطاق.
- كلمات المرور مجزّأة بـ scrypt ولا تظهر في أي رد، مع قفل مؤقت بعد 5 محاولات دخول فاشلة.
- الملفات الثابتة من قائمة بيضاء فقط (`index.html`, `manifest.json`, `assets/`)، فلا يمكن تحميل `data/db.json` أو `server.js` من المتصفح.
- ترويسات أمان وCSP؛ لا يوجد JavaScript داخل HTML؛ وكل نص يُهرَّب قبل عرضه.

## ما لم يُنجَز بعد (بصراحة)
- لا توجد واجهة إدارة لإسناد المعلمين إلى الأفواج أو إضافة المستخدمين؛ يتم ذلك حاليًا في `data/db.json` (`teacher_groups`, `users`).
- قاعدة JSON ومعالج واحد والجلسات في الذاكرة: مناسبة للتطوير فقط. الإنتاج الحقيقي يحتاج قاعدة بيانات وخدمات تخزين ونشر آمن؛ هذه النسخة مخصصة للتطوير المحلي والاختبار.
- لا HTTPS ولا نسخ احتياطي ولا سجل تدقيق بعد.
- معادلة الحضور قابلة للتعديل في `report_settings` داخل `db.json` (وزن التأخر 0.75، والغياب بعذر لا يُحتسب ضد الطالب).

## V57 — legacy service routing
The Oregon Render service cannot resolve the Frankfurt-only PostgreSQL internal hostname. V57 adds an explicit, opt-in redirect-only mode for that legacy service. When `ACADEMY_REDIRECT_TO_FRANKFURT=1` is set on the Oregon service, requests are redirected to the canonical Frankfurt app, while its health check returns a small healthy response without opening the remote database. The variable must be set only on the Oregon service; do not set it on Frankfurt.

- Expanded the curriculum from the initial pack to 26 lessons and 92 practice questions across Quran vocabulary, revision, character and bullying prevention, planning, critical thinking, family communication, health and movement, financial responsibility, balanced recreation, Arabic speaking, seerah timeline, and asking for help.
