# أكاديمية الإحسان في بناء الإنسان

**الشعار:** منارات العلم وبساتين الإحسان.

## البنية الفعلية — 22 نوفمبر 2026

المشروع يعمل على Cloudflare، وله واجهتان منفصلتان:

| الجزء | الغرض | مشروع Cloudflare | فرع النشر | المصدر |
|---|---|---|---|---|
| أكاديمية الإحسان | منصة داخلية للطلاب والشيخ والإدارة | `ihsan` | `migration/cloudflare-student-platform` | `deploy/cloudflare/` |
| بوابة التيسير | التعريف العام والانضمام والمساهمات | `a-taysir` | `feat/taysir-public-portal` | `site-taysir/` |

- بوابة التيسير العامة: https://a-taysir.pages.dev/
- عنوان Pages التقني المعيّن حاليًا للمنصة الداخلية: `a-ihsan.pages.dev`. هذا العنوان ليس قرارًا نهائيًا بشأن النطاق الذي يعتمده صاحب المشروع للطلاب؛ لا تغيّره ولا تنشئ نطاقًا بديلًا دون تحقق واعتماد.
- المنصة الداخلية مستبعدة عمدًا من فهرسة محركات البحث. بوابة التيسير هي واجهة التعريف العامة القابلة للفهرسة.
- قاعدة البيانات الفعلية D1 مرتبطة بمشروع الأكاديمية. لا تحذفها ولا تنفّذ عليها ترحيلًا يدويًا أو إعادة تهيئة أثناء تنظيف الملفات.

## حالة الوظائف

- تسجيل الدخول وكلمات المرور وربط هوية Google واسترداد الحساب محكومة بواجهات API والصلاحيات؛ إعدادات OAuth في Google Console والتحقق الفعلي من النطاق يظلان جزءًا من اختبار القبول.
- بطاقات الطالب وQR والمتجر ونظام النقاط موجودة. لا تُنشأ جوائز أو أسعار أو مخزونات وهمية؛ تعتمد الإدارة المكافآت الحقيقية.
- رصيد الإنجاز ورصيد المتجر منفصلان في دفتر الحركات. لا تُحوّل الأرصدة التاريخية ولا تعِد احتسابها دون خطة ترحيل احتياطية واختبار استعادة.
- تسجيل الطالب للحفظ الجديد والتثبيت يبقى معلّقًا حتى اعتماد الشيخ؛ الرفض يتطلب سببًا، والتصحيح وإعادة الإرسال لا يكرران النقاط.
- خطط الحفظ والتثبيت والورد السابقة تجريبية وقيد المراجعة، وليست تكليفًا معتمدًا تلقائيًا.
- نظام المستويات مؤجل؛ تبقى الأوسمة والإنجازات دون ترقيات رقمية.
- التطبيق PWA قابل للتثبيت، ويخزّن غلاف التطبيق والملفات الثابتة. واجهات API لا تُخزّن في Service Worker؛ لذلك لا يُسوّق الوضع غير المتصل على أنه يتيح كل عمليات المنصة.

## التحقق

في 22 نوفمبر 2026 اجتاز الفرع اختبارات البناء والتكامل، بما فيها مسارات الطالب والمتجر والنقاط، اعتماد القرآن ورفضه وإعادة الإرسال، النسخ الاحتياطي والاستعادة، الصلاحيات، المسابقات، QR والبطاقات والمهام، والتسجيل وطلبات الانضمام.

نجاح الاختبارات الآلية لا يغني عن اختبار قبول حي بحسابات معتمدة على الهاتف والحاسوب. لا تُنشئ حسابات اختبار في قاعدة الإنتاج ولا تعدّل سجلات الطلاب الحقيقيين لهذا الغرض.

## ما بقي قبل إعلان الاكتمال

1. اعتماد النطاق النهائي الذي سيُعطى للطلاب؛ لا يُفترض أن عنوان Pages الحالي هو النطاق النهائي.
2. اختبار Google OAuth وSearch Console فعليًا من لوحة Google، والتحقق من ظهور بوابة التيسير وفهرستها.
3. تجربة التثبيت والاستخدام على Android وWindows، بما في ذلك حدود العمل دون اتصال.
4. فُحصت سلامة الأرشيف وملفاته؛ راجع `docs/ASSETS-AUDIT.md` لنتائج المطابقة والخصوصية، وما زال اعتماد الصور المرشحة قبل النشر مطلوبًا.
5. إدخال المكافآت وصورها وتكاليفها ومخزونها الحقيقية بعد اعتماد الإدارة.
6. استكمال فصل صلاحيات الإدارة والشيخ والمشرفين وكبير المشرفين قبل توسيع الاستخدام.
7. مراجعة مشروعي Pages التاريخيين قبل حذفهما؛ لا توجد حاجة إلى حذف قاعدة البيانات أو سجلات الطلاب لتنظيف روابط النشر.

## قواعد المحافظة على البيانات

- لا تحذف طالبًا أو حسابًا أو بطاقة QR أو حركة نقاط أو سجل قرآن لمجرد التنظيف.
- لا تعِد تشغيل إعداد الحسابات الجماعي؛ قد يعيد تعيين كلمات مرور حسابات موجودة.
- لا تعدّل قاعدة D1 مباشرة. استخدم ترحيلات إضافية idempotent، ونسخة احتياطية واختبار استعادة قبل أي تغيير.
- لا تضع كلمات مرور أو أسرارًا أو ملفات دخول في Git.
- ملفات الجذر القديمة ومصادر الخادم السابقة تاريخية وليست مصدر نشر الأكاديمية الحالي.

## مسارات العمل

- API والمصادقة وD1: `deploy/cloudflare/src/index.js`
- واجهة الأكاديمية: `deploy/cloudflare/site/app.js`
- التصميم: `deploy/cloudflare/site/style.css`
- PWA: `deploy/cloudflare/site/manifest.json` و`service-worker.js`
- ترحيلات D1: `deploy/cloudflare/migrations/`
- اختبارات الحماية والتكامل: `deploy/cloudflare/scripts/`
- بوابة التيسير: `site-taysir/`
