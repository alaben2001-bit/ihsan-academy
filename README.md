نسخة تطوير محلية متصلة بطبقة تخزين قابلة للتبديل. **JSON هو الافتراضي الآمن، وSQLite أصبح مسارًا حقيقيًا قابلًا للاختبار دون ادعاء اتصال سحابي غير موجود.**

## تخزين V31
- `ACADEMY_STORAGE=json` — الافتراضي، باستخدام `data/db.json`.
- `ACADEMY_STORAGE=sqlite` — SQLite حقيقي عبر `node:sqlite` ويتطلب Node.js 22+.
- `npm run migrate:sqlite -- data/db.json data/academy-v30.sqlite` — هجرة JSON إلى SQLite مع تحقق round-trip.
- `npm run migrate:json -- data/academy-v30.sqlite data/db.restored-v30.json` — رجوع SQLite إلى JSON.
- `npm run health:storage` — فحص صحة التخزين.
- `GET /api/health` — فحص عام مختصر.
- `GET /api/admin/health/storage` — فحص تفصيلي للمدير بعد تسجيل الدخول.

SQLite في V31 هو **جسر تخزين** يحافظ على نموذج البيانات الحالي: كل مجموعة مصفوفة تُحفظ في جدول JSON، والحقول الكائنية في `academy_meta`. هذا مقصود حتى ننتقل لاحقًا إلى schema إنتاجي منظم تدريجيًا بدل إعادة بناء الأكاديمية دفعة واحدة.

## النسخ والترحيل
V30 يدعم backup/restore الموجودين من V29، وأضاف مسارًا قابلًا للعكس بين JSON وSQLite. لا تُلغى قاعدة JSON تلقائيًا عند تفعيل SQLite.

## ما الجديد في V18 — النسخة المحسّنة
- **المعلم:** قوائم اختيار بدل كتابة s1/t1 (الفوج، التاريخ، حالة الحضور، الاختبار).
- **الحضور الجماعي:** كشف بأسماء الفوج وأربع حالات (حاضر/متأخر/غائب/غائب بعذر) وحفظ الجميع مرة واحدة، وإعادة الحفظ تعدّل ولا تكرّر.
- **إنشاء الاختبارات من الواجهة:** العنوان، المادة، الفوج، التاريخ، الدرجة القصوى، الوصف.
- **جدول الدرجات:** الطالب | الدرجة | ملاحظة، مع التحقق من الدرجة القصوى في الخادم.
- **ملف الطالب (المركز):** نظرة عامة، الحضور، المنهج، الحفظ، المراجعة، الاختبارات والدرجات، الأهداف، الملاحظات، التقرير.
- **ملاحظات المعلم:** التصنيف (تعليمي/سلوكي/تحفيزي/متابعة) + خيار «مشاركة مع الطالب وولي الأمر». الافتراضي: للمعلمين فقط.
- **التقرير الشهري التلقائي:** يُحسب من الحضور والدرجات والحفظ والأهداف والملاحظات، ويولّد ملخصًا ونقاط قوة وما يحتاج تحسينًا، ويقارن الطالب بنفسه في الشهر السابق فقط. يمكن حفظه في السجل.
- **الطباعة / حفظ PDF:** زر «طباعة / حفظ PDF» يفتح تقريرًا بتنسيق A4 جاهزًا للطباعة أو الحفظ كـ PDF من المتصفح. (ملف PDF مولَّد من الخادم مؤجل إلى V18.)
- **لوحة ولي الأمر:** أبناؤه فقط، ولكل ابن ملف كامل للقراءة فقط وتقرير شهري، وتُعرض له الملاحظات المشاركة فقط.
- **التصميم:** عربي RTL، أخضر/بيج/أبيض، يعمل على الهاتف والكمبيوتر.
- **V18 — تجربة الدرس:** يمكن للطالب فتح الدرس وقراءة هدفه ومحتواه ومدة تقديرية، ثم تسجيل الإكمال من داخل نافذة الدرس.
- **V18 — استكمال التعلم:** يظهر للطالب الدرس التالي مباشرة في بطاقة «الخطوة التالية».
- **V18 — البحث:** بحث فوري داخل قائمة الدروس.
- **V18 — عزل الدروس:** مسار عرض الدرس يتحقق من صلاحية الوصول من الخادم قبل إرجاع المحتوى.

## الأمان (يُطبَّق في الخادم)
- الدور يؤخذ من الجلسة فقط؛ أي role أو student_id أو parent_id من المتصفح لا يمنح شيئًا.
- الطالب يرى نفسه فقط، وولي الأمر أبناءه فقط، والمعلم طلاب أفواجه فقط (جدول `teacher_groups`)، والإدارة الكل.
- الأفواج والمنشورات والإشعارات والاختبارات والحفظ والأهداف كلها مفلترة حسب النطاق.
- كلمات المرور مجزّأة بـ scrypt ولا تظهر في أي رد، مع قفل مؤقت بعد 5 محاولات دخول فاشلة.
- الملفات الثابتة من قائمة بيضاء فقط (`index.html`, `manifest.json`, `assets/`)، فلا يمكن تحميل `data/db.json` أو `server.js` من المتصفح.
- ترويسات أمان وCSP؛ لا يوجد JavaScript داخل HTML؛ وكل نص يُهرَّب قبل عرضه.

## ما لم يُنجَز بعد (بصراحة)
- لا توجد واجهة إدارة لإسناد المعلمين إلى الأفواج أو إضافة المستخدمين؛ يتم ذلك حاليًا في `data/db.json` (`teacher_groups`, `users`).
- قاعدة JSON ومعالج واحد والجلسات في الذاكرة: مناسبة للتطوير فقط. الإنتاج الحقيقي يحتاج قاعدة بيانات وخدمات تخزين ونشر آمن؛ هذه النسخة مخصصة للتطوير المحلي والاختبار.
- لا HTTPS ولا نسخ احتياطي ولا سجل تدقيق بعد.
- معادلة الحضور قابلة للتعديل في `report_settings` داخل `db.json` (وزن التأخر 0.75، والغياب بعذر لا يُحتسب ضد الطالب).

## V31 — النواة الإنتاجية المنظمة

أضيفت نواة SQLite منظمة للمجالات الأساسية والمدرسة القرآنية، مع مفاتيح خارجية وفهارس وهجرة قابلة للعكس. الخادم لم يُحوّل إليها بعد؛ تبقى طبقة V30 الحالية هي مسار التشغيل، بينما تعمل نواة V31 كهدف إنتاجي متحقق منه.

أوامر جديدة:
- `npm run migrate:core` — هجرة JSON إلى النواة المنظمة.

## V49 — إضافات التشغيل الأخيرة
- بوابة دخول مستقلة للمدرسة القرآنية من شاشة الدخول، مع سجل مدارس قرآنية قابل للإدارة لاحقًا.
- فرق صغيرة داخل الأفواج: اسم، وصف، أعضاء، مهام، ومشرفون من كبار الطلبة. المشرف لا يرث صلاحيات المعلم أو المدير.
- إصلاح تسمية واجهة المعلم: **طلبتي** بدل **أبنائي**؛ **أبنائي** بقيت لولي الأمر فقط.
- إنشاء المدير الأول في بيئة الإنتاج يتم عبر `ACADEMY_BOOTSTRAP_ADMIN_*` إذا لم يوجد مدير، ولا تُحفظ كلمة مرور إنتاجية ثابتة داخل المستودع.
- تشديد رفع ملفات مكتبة الشيخ ومنع أنواع HTML/JS/SVG من التحول إلى محتوى قابل للتنفيذ داخل نفس الأصل.
- اختبار إضافي للفرق والصلاحيات ومدخل المدرسة القرآنية.

### ملاحظة أمنية
هذه الإضافات لا تعني أن الاستضافة نفسها أصبحت موجودة أو أن حساب Render/قاعدة PostgreSQL تم إنشاؤهما؛ النشر الخارجي يحتاج ربط الحسابات والبيئة السرية الفعلية.
